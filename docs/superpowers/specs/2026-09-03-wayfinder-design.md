# wayfinder — design

**Ημερομηνία:** 2026-09-03
**Κατάσταση:** εγκεκριμένο σχέδιο, αναθεωρημένο μετά από review, εκκρεμεί implementation plan

## Τι είναι

Δημόσιο site που δείχνει στοιχεία ελληνικών επιχειρήσεων, αντλώντας από το επίσημο
OpenData API του ΓΕΜΗ. Στατικό frontend σε GitHub Pages, δωρεάν σε όλη τη διαδρομή.

Ο χρήστης δίνει ΑΦΜ, αριθμό ΓΕΜΗ ή επωνυμία και βλέπει τα στοιχεία δημοσιότητας της
επιχείρησης, τα δημόσια έγγραφά της, και — όπου έχουμε καταφέρει να τα εξαγάγουμε με
βεβαιότητα — οικονομικά μεγέθη από τους δημοσιευμένους ισολογισμούς.

**Η κεντρική αρχή:** ένα λάθος νούμερο είναι χειρότερο από κανένα νούμερο. Όλο το σχέδιο
του extractor και της δημοσίευσης υπάρχει για να επιβάλει αυτό.

## Πηγή δεδομένων

**ΓΕΜΗ OpenData API** — `https://opendata-api.businessportal.gr/api/opendata/v1`

- OpenAPI 2.0 spec: `https://opendata-api.businessportal.gr/api-docs`
- Auth: header `api_key`
- Άδεια: **ODC-BY-1.0** — επιτρέπει αναδημοσίευση και εμπορική χρήση, **απαιτεί αναφορά πηγής**
- Εγγραφή: `https://opendata.businessportal.gr/register/` — δωρεάν, με έγκριση της ΚΥ ΓΕΜΗ
- Το δημόσιο test key `api-docs-key` επιστρέφει 401 στο live API (επαληθεύτηκε 2026-09-03)

### Endpoints που χρησιμοποιούμε

| Endpoint | Χρήση |
|---|---|
| `GET /companies` | Αναζήτηση: `afm`, `arGemi`, `name`, `activities`, `legalTypes`, `municipalities`, `prefectures`, `statuses`, `isActive`, pagination |
| `GET /companies/{arGemi}` | Στοιχεία δημοσιότητας μιας επιχείρησης |
| `GET /companies/{arGemi}/documents` | Λίστα δημόσιων εγγράφων (εδώ ζουν οι ισολογισμοί) |
| `GET /downloadFile?key=&elementId=` | Λήψη εγγράφου (PDF) — **απαιτεί κι αυτό `api_key`** |
| `GET /metadata/*` | Παραμετρικά: δραστηριότητες, νομοί, δήμοι, καταστάσεις, νομικές μορφές, υπηρεσίες ΓΕΜΗ, θέματα αποφάσεων |

**Τι δεν δίνει το API:** οικονομικά μεγέθη ως δεδομένα. Οι ισολογισμοί υπάρχουν μόνο ως
PDF μέσω `/downloadFile`. Αυτό είναι όλη η δυσκολία του project.

## Αρχιτεκτονική

```
GitHub Pages (Astro, static)
      │ fetch
      ▼
Cloudflare Worker (free plan)  ──▶  ΓΕΜΗ OpenData API
   κρατά το GEMI_API_KEY               (στοιχεία δημοσιότητας, live)
   CORS + cache + authenticated PDF proxy
      │ POST request-financials
      ▼
Cloudflare Queue (free plan)
      │ HTTP pull consumer
      ▼
GitHub Actions (Python)
   pull batch (lease) → downloadFile → extractor → validate
   → commit → astro build → deploy Pages → ack μηνύματα
```

### Γιατί ο parser τρέχει σε GitHub Actions και όχι σε Worker

Το Workers free plan δίνει **10ms CPU ανά HTTP request** (paid: 30s). Parsing PDF θέλει
δευτερόλεπτα CPU, άρα δεν χωράει στο free tier — ούτε σε queue consumer, όπου το όριο
των 15 λεπτών είναι *wall time*, όχι CPU.

Οι standard GitHub-hosted runners είναι **δωρεάν για public repos** (υπό τα γενικά όρια
χρήσης του GitHub, όχι απεριόριστοι), με πλήρες Python περιβάλλον και OCR. Το τίμημα
είναι latency: τα οικονομικά εμφανίζονται λεπτά αργότερα. Δεκτό, γιατί το site είναι
χρήσιμο και χωρίς αυτά.

### Γιατί Queue και όχι δικός μας πίνακας εργασιών σε D1

Ένα ζευγάρι `GET pending` / `POST clear` δεν είναι ουρά: δύο runs παίρνουν τις ίδιες
εργασίες, ένα crash μετά την εξαγωγή αλλά πριν το clear διπλασιάζει δουλειά, και ένα
clear μετά από μερική επιτυχία σβήνει και όσα απέτυχαν. Τα Cloudflare Queues είναι στο
free plan από τον Φεβρουάριο 2026 και ο **HTTP pull consumer** δίνει έτοιμα lease IDs,
visibility timeout, per-message ack και retries. Δεν ξαναγράφουμε queue semantics.

Το GitHub Actions τραβάει από την ουρά με scoped Cloudflare API token.

**Περιορισμός:** στο free tier η διατήρηση μηνυμάτων είναι **24 ώρες**. Σε συνδυασμό με
το ότι τα schedules του GitHub καθυστερούν ή χάνονται, χρειάζεται alert όταν το
παλαιότερο μήνυμα ξεπερνά τις λίγες ώρες.

## Components

Τέσσερα, με σκοπίμως στενά όρια.

### 1. `site/` — Astro, στατικό

| Route | Σημείωση |
|---|---|
| `/` | αναζήτηση |
| `/company/?arGemi=...` | **query param, όχι dynamic path** |
| `/about` | αναφορά πηγής, ODC-BY |

Το GitHub Pages είναι στατικό hosting: ένα `/company/[arGemi]` θα απαιτούσε να έχουν
προ-χτιστεί όλες οι διαδρομές. Επειδή η αναζήτηση είναι live, η σελίδα εταιρείας είναι
**ένα shell** που γεμίζει client-side από το Worker.

Δεν ξέρει τίποτα για το ΓΕΜΗ. Μιλάει μόνο στο Worker και διαβάζει στατικά JSON.
Zero JS by default· islands στο search box, στη σελίδα εταιρείας και στα γραφήματα.

### 2. `worker/` — Cloudflare Worker

| Route | Κάνει |
|---|---|
| `GET /api/search?q=` | Proxy στο `/companies`, normalize του query |
| `GET /api/company/:arGemi` | Proxy + cache |
| `GET /api/company/:arGemi/documents` | Proxy + cache |
| `GET /api/company/:arGemi/documents/:elementId/download` | Authenticated proxy στο `/downloadFile`· **επαληθεύει ότι το έγγραφο ανήκει σε αυτή την εταιρεία** πριν το σερβίρει |
| `POST /api/request-financials/:arGemi` | Validate `arGemi`, rate-limit, `Queue.send()` |

Cache: Cloudflare Cache API. Οι απαντήσεις κρατιούνται **πολύ περισσότερο από το TTL
φρεσκάδας** και αποθηκεύουν `fetched_at`· η απόφαση «αρκετά φρέσκο» παίρνεται στην
ανάγνωση. Αλλιώς μια ληγμένη εγγραφή δεν μπορεί να σερβιριστεί σε upstream αστοχία,
που ακυρώνει όλη την υπόσχεση του stale-cache.

**Δεν κάνει parsing. Δεν κάνει OCR. Δεν αποθηκεύει οικονομικά.**

### 3. `extractor/` — Python

Δύο επίπεδα, γιατί το PDF από μόνο του δεν ξέρει σε ποια εταιρεία ανήκει:

```python
extract(pdf_bytes)                    -> ExtractedFacts    # καθαρό, χωρίς context
build_record(facts, source_context)   -> CompanyFinancials # + arGemi, document id, sha256
```

Το πρώτο δεν ξέρει τίποτα για Cloudflare, GitHub ή HTTP και τεστάρεται με σκέτα αρχεία.

**Ταξινόμηση πριν από εξαγωγή.** Πριν γίνει δεκτή οποιαδήποτε τιμή, το έγγραφο πρέπει να
δώσει: εταιρεία, περίοδο (έναρξη + λήξη), τύπο κατάστασης, εμβέλεια (Εταιρεία / Όμιλος),
νόμισμα, πολλαπλασιαστή (μονάδες / χιλιάδες), επικεφαλίδες στηλών, και έκδοση
(αρχική / αναμορφωμένη). Χωρίς αυτά, τίποτα δεν δημοσιεύεται.

#### Σχήμα εξόδου

```json
{
  "ar_gemi": "054414421000",
  "source_document_id": "...",
  "source_sha256": "...",
  "retrieved_at": "2026-09-03T12:00:00Z",
  "period_start": "2024-01-01",
  "period_end": "2024-12-31",
  "scope": "company",
  "statement_version": "original",
  "status": "parsed",
  "figures": {
    "turnover": {
      "value": "1234567.89",
      "currency": "EUR",
      "scale": 1,
      "page": 3,
      "raw_text": "1.234.567,89",
      "method": "text",
      "validation": ["column_header_matched", "unit_identified"]
    }
  }
}
```

Κανόνες που επιβάλλει το σχήμα:

- **Ποσά ως decimal strings**, ποτέ floats.
- **Μια τιμή που λείπει είναι `null` ή απούσα — ποτέ `0`.** Το `0` επιτρέπεται μόνο αν το
  έγγραφο λέει κυριολεκτικά μηδέν.
- Κάθε ποσό κουβαλά **δική του** σελίδα, raw text, μέθοδο και ελέγχους. Δεν υπάρχει ένα
  top-level `source_page` — διαφορετικά μεγέθη έρχονται από διαφορετικές σελίδες.
- Ένα αρχείο ανά `(arGemi, period_end, scope, statement_version)`, όχι ανά εταιρεία.
  Αλλιώς δεν χωρούν πολλαπλές χρήσεις, αναμορφώσεις, ή ενοποιημένες καταστάσεις.
- **EBITDA δεν εξάγεται στο v1.** Δεν είναι τυποποιημένη γραμμή· θα ήταν συμπέρασμα.

`status` ∈ `parsed` | `partial` | `needs_review` | `unparseable`.
**Μόνο τα `parsed` και `partial` δημοσιεύουν νούμερα**, και μόνο για πεδία που πέρασαν
όλους τους ελέγχους. Το `needs_review` υπάρχει ακριβώς για την περίπτωση που βρέθηκε τιμή
αλλά δεν είναι βέβαιο σε ποια στήλη ή περίοδο ανήκει — εκεί δεν βγαίνει τίποτα.

Ένα μέγεθος γίνεται δημόσιο μόνο όταν: περίοδος, στήλη, εμβέλεια, νόμισμα και μονάδα
είναι μονοσήμαντα· υπάρχει ακριβώς ένας υποψήφιος· κρατιέται ο εντοπιστής τεκμηρίου·
και όλη η εγγραφή περνά versioned JSON Schema validation πριν το commit.

### 4. `data/financials/` — το dataset

Committed JSON. Είναι ταυτόχρονα η αποθήκη του site και το δημόσιο open-data προϊόν.
Το Astro build το αντιγράφει στο `public/data/financials/`.

## Ροή δεδομένων

1. Ο χρήστης αναζητά → site → Worker → ΓΕΜΗ → αποτελέσματα.
2. Ανοίγει εταιρεία → Worker: στοιχεία δημοσιότητας + λίστα εγγράφων. **Αμέσως.**
3. Το site ζητά `/data/financials/<arGemi>/index.json`.
   - Υπάρχει και καλύπτει το τρέχον `source_document_id` → δείχνει τα μεγέθη.
   - Λείπει **ή είναι παλαιότερο από το νεότερο έγγραφο** → μήνυμα «δεν έχουν
     επεξεργαστεί ακόμα» + links στα PDF, και `POST /api/request-financials`.
     Ο έλεγχος γίνεται στο document id, όχι στην ύπαρξη αρχείου — αλλιώς μια νέα
     δημοσίευση δεν θα έμπαινε ποτέ στην ουρά.
4. GitHub Actions (cron + `workflow_dispatch`) → pull batch με 30–60′ visibility timeout
   → συγχώνευση διπλών `arGemi` → κατέβασμα → extract → validate → **ένα commit** →
   `astro build` → deploy Pages → **μετά** ack.

**Το ack γίνεται μόνο μετά από επιτυχές deploy.** Ένα αποτυχημένο deploy δεν μετράει ως
ολοκλήρωση.

### Απαιτήσεις του workflow

- `concurrency` group — δύο runs δεν γράφουν μαζί στο default branch.
- Το ίδιο workflow **χτίζει και κάνει deploy** τις Pages. Ένα commit με `GITHUB_TOKEN`
  δεν σκανδαλίζει άλλο workflow ούτε Pages build· χωρίς αυτό, τα δεδομένα δεν θα
  δημοσιεύονταν ποτέ.
- `workflow_dispatch` πάντα διαθέσιμο. Τα scheduled workflows σε public repo
  απενεργοποιούνται μετά από 60 ημέρες χωρίς δραστηριότητα, και καθυστερούν στην κορυφή
  της ώρας — προγραμματίζουμε εκτός στρογγυλής ώρας.
- Δικαιώματα: μόνο `contents`, `pages`, OIDC.
- Το Actions χρειάζεται **κι αυτό** το `GEMI_API_KEY` (ως GitHub secret) για το
  `downloadFile`. Υπάρχουν δύο αντίγραφα του κλειδιού· το δηλώνουμε αντί να
  προσποιούμαστε ότι υπάρχει ένα.
- Όρια ενάντια σε κακόβουλα ή χαλασμένα PDF: download timeout, μέγιστα bytes και σελίδες,
  έλεγχος PDF magic/MIME, όριο αποσυμπίεσης, OCR timeout, εφήμερο βήμα parsing.

## Χειρισμός σφαλμάτων

| Κατάσταση | Συμπεριφορά |
|---|---|
| ΓΕΜΗ API κάτω / 5xx | Σερβίρει cached αντίγραφο με banner ηλικίας (γι' αυτό το cache ζει πέρα από το TTL φρεσκάδας) |
| ΓΕΜΗ 401 (key έληξε) | Worker λογάρει, site δείχνει σφάλμα υπηρεσίας — όχι κενή σελίδα |
| Rate limit ΓΕΜΗ | Backoff στο Worker, 429 προς τα πάνω με `Retry-After` |
| Δεν βρέθηκε εταιρεία | Καθαρό «δεν βρέθηκε», όχι κενό |
| Οικονομικά μη διαθέσιμα | Ρητό μήνυμα + link στο authenticated PDF route |
| PDF σκαναρισμένο / OCR απέτυχε | `unparseable` — το site το λέει, δίνει το PDF |
| Ασαφής στήλη ή περίοδος | `needs_review` — **κανένα νούμερο δημόσιο** |
| Μερική εξαγωγή | `partial` — μόνο τα πεδία που πέρασαν όλους τους ελέγχους |
| Εγγραφή δεν περνά JSON Schema | Δεν γίνεται commit· το μήνυμα επιστρέφει στην ουρά |

## Testing

Τα tests του extractor γράφονται **πριν** τον extractor. Είναι το συμβόλαιο.

### Τα τρία acceptance tests

1. **Corpus χωρίς false positives.** Πραγματικά fixtures που περιέχουν: στήλη τρέχουσας
   και προηγούμενης χρήσης, στήλη Εταιρείας και Ομίλου, «ποσά σε χιλιάδες», αρνητικά σε
   παρενθέσεις, αναμορφωμένη κατάσταση, και ένα ασαφές σκαναρισμένο. Κάθε εμφανιζόμενο
   ποσό ταιριάζει ακριβώς με golden value, raw text, σελίδα, περίοδο, εμβέλεια, μονάδα.
   **Τα ασαφή δεν παράγουν κανένα δημόσιο νούμερο — ούτε `0`, ούτε best guess.**

2. **Crash και επαναπαράδοση.** Ίδια εταιρεία δύο φορές στην ουρά, προσομοίωση crash μετά
   την εξαγωγή αλλά πριν το ack, ξανατρέξιμο με επικαλυπτόμενους consumers. Κριτήριο:
   ένα ντετερμινιστικό JSON, καμία χαμένη εργασία, retry στα παροδικά, ack μόνο μετά από
   commit **και** επιτυχές deploy.

3. **Ασφάλεια δημοσίευσης στον browser.** Τροφοδοτούμε το build με έγκυρη, μερική,
   παλιά, ασύμβατη και χαλασμένη εγγραφή. Κριτήριο: νούμερο εμφανίζεται μόνο για πεδία
   που περνούν το schema και είναι publishable· κάθε άλλη περίπτωση δείχνει ρητή
   κατάσταση (μη διαθέσιμο / ασαφές / παλιό) και λειτουργικό link στο PDF.

Υποστηρικτικά: `worker/` με vitest + Miniflare (και τα 5 routes, cache hit/miss, 401,
429, backoff, έλεγχος ότι το έγγραφο ανήκει στην εταιρεία)· `site/` build check.

## Ρίσκα, κατά σειρά σοβαρότητας

1. **Έγκριση API key από την ΚΥ ΓΕΜΗ.** Μπλοκάρει τα πάντα, άγνωστη διάρκεια, εκτός
   ελέγχου μας. Υποβάλλεται πρώτο, πριν γραφτεί κώδικας.
2. **Λάθος στήλη, όχι λάθος OCR.** Η πιθανότερη πρώτη αστοχία δεν είναι ένα crash — είναι
   ένα σίγουρα δημοσιευμένο νούμερο από τη στήλη προηγούμενης χρήσης, από τον Όμιλο αντί
   της Εταιρείας, ή σε χιλιάδες αντί μονάδες. Όλο το `needs_review` μονοπάτι υπάρχει γι'
   αυτό.
3. **Ελληνική αριθμητική σημειογραφία.** `1.234.567,89`, αρνητικά σε παρενθέσεις, παύλα
   που σημαίνει άλλοτε μηδέν και άλλοτε μη διαθέσιμο, OCR που μπερδεύει `0/O/Ο` και
   `1/I/Ι`. Απαιτεί ρητό parser, όχι `float()`.
4. **Σκαναρισμένα PDF.** Αν το δείγμα είναι κυρίως εικόνες, το OCR γίνεται το κύριο
   πρόβλημα. Απόφαση μετά το δείγμα.
5. **24ωρη διατήρηση στο free Queue + αναξιόπιστο cron.** Alert όταν το παλαιότερο
   μήνυμα ξεπερνά τις λίγες ώρες· `workflow_dispatch` ως χειροκίνητη διέξοδος.

Δευτερεύοντα: άγνωστα rate limits ΓΕΜΗ (μετριασμός: επιθετικό cache)· υποχρέωση ODC-BY
(αναφορά πηγής σε footer κάθε σελίδας και στο `/about`, από την πρώτη μέρα).
